# Domain documentation

Use one shared context for the current small monorepo.

- Read [CONTEXT.md](../../CONTEXT.md) when domain terminology is relevant.
- Read only the ADRs in [docs/adr/](../adr/) relevant to the current task.
- Use the glossary's terms consistently in explanations, tickets, and reviews.
- Add terms only after they have been explained and agreed; do not anticipate a large domain model.
- Record significant agreed decisions as numbered ADRs: context, decision, consequences, and remaining questions.
- An accepted ADR records a design decision, not evidence of implementation.
- If a proposal conflicts with an ADR, explain the conflict and revisit the decision with the learner.
- Keep task status in [.scratch](../../.scratch/README.md), collaboration rules in [AGENTS.md](../../AGENTS.md), and decision rationale in ADRs. Avoid copying the same information between them.
- No CONTEXT-MAP.md or per-package glossaries are needed yet.
